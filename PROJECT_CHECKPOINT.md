# Project checkpoint

Updated: 2026-09-01

## Current stage

Публичное название продукта — **SlovoKrok**. Название репозитория, его remote
URL и стабильные технические идентификаторы не переименовываются.
Крупные пользовательские этапы публикуются в корневом `UPDATES.md`; первая
запись фиксирует завершение и ручную приёмку Module 1.

Frontend course decomposition завершена. `courseProgress.ts` теперь содержит
чистые scheduling, summary и reset-scope transforms; controller сохраняет
functional React updates, а views получают typed `model/actions`. Reset scope
отделяет lesson slugs от activity IDs и сохраняет чужой/неизвестный progress.
`CourseScreen.tsx` остаётся компактным orchestrator. Tutor UI по решению
владельца отложен и исключён из текущего frontend roadmap; существующий backend
tutor endpoint остаётся dormant для совместимости. `CourseState` v1, persisted
`chatHistories`, storage keys и большая миграция не изменены.

Репрезентативный ручной UI-аудит выполнен в изолированном runtime на отдельной
SQLite и портах `3100/8100`, без изменения пользовательского прогресса. Проверены
чистое и завершённое состояния, material/practice/error/reload/final/module
transition, дополнительные разделы, light/dark, размеры текста и ширины 390,
768 и desktop. Исправлены vocabulary sync и два responsive-дефекта: шапка
переносится до появления tablet overflow, а mobile material использует
компактный выбор темы вместо длинного списка перед статьёй.
Hydration resilience также исправлена: последние данные курса постоянно
кэшируются в существующих legacy localStorage keys, а GET/PUT автоматически
повторяются после временной недоступности backend без ручного reload.

Новый приоритет владельца — стабильное добавление и обновление контента; UI и
Tutor остаются отложенными. Content architecture унифицирована: каждый
`moduleN/index.ts` экспортирует готовый `CourseModule`, а `a1Course.ts` является
только реестром восьми модулей. Общий `moduleFactory.ts` сверяет регистрацию с
roadmap, назначает порядок, выводит `lessonSlugs` из lessonGroups и отклоняет
пропущенные, лишние и повторные темы. Для compact Modules 7–8 тем же контрактом
проверяется полный набор content-файлов.

Статус владельца по Module 1: все 14 тем проверены и согласованы вручную;
материалы, упражнения, тесты и работа модуля одобрены. Ручная приёмка Module 1
завершена. Следующий продуктовый этап — работа над Module 2.

Для следующих отчётов владельца создан и установлен личный навык
`$a1-course-progress-tracker`: он переводит сообщения о готовых, загруженных,
проверенных и отложенных темах в построчные статусы учебного roadmap и краткий
статус checkpoint, не изменяя содержимое уроков.

Module 1, тема 11 `days-and-months` сверена с семистраничным PDF владельца:
материал следует маршруту «неделя → когда? → месяцы → дата → расписание», шесть
существующих `days-step-*` ID сохранены, а упражнения источника перенесены в
отдельный интерактивный финальный тест из шести заданий. Свободный план недели
адаптирован в закрытый выбор корректного плана, чтобы проверка не зависела от
одного образца ответа.

Module 1, тема 12 `personal-pronouns` сверена с семистраничным PDF владельца:
пять существующих `pronouns-step-*` ID сохранены, материал ограничен личными
местоимениями, формами `byť`, вежливым `vy`, опущением и контрастом. Падежные и
притяжательные формы удалены из этой темы как преждевременные; шесть упражнений
источника перенесены в отдельный интерактивный финальный тест с построчной
проверкой переводов.

Module 1, тема 13 `verb-byt` сверена с семистраничным PDF владельца: пять
существующих `byt-step-*` ID сохранены, а материал следует маршруту «настоящее
→ отрицание → вопрос → значения → минимальные прошлое/будущее». Шесть
упражнений источника перенесены в отдельный интерактивный финальный тест;
естественные варианты `Sú oni v škole?` и `Sú v škole?` принимаются одинаково,
а свободный рассказ адаптирован в закрытый выбор согласованного профиля.

Module 1, тема 14 `question-words` сверена с семистраничным PDF владельца:
пять автоматически построенных `m1-question-words-step-*` ID сохранены,
материал следует маршруту «кто/что → где/куда → когда/как → порядок →
практика», а шесть упражнений вынесены в отдельный интерактивный финальный
тест. Ошибка задания источника `čia auto` исправлена по нормативному ответу
`čie auto`; открытое интервью адаптировано в шесть закрытых A1-строк без
преждевременного инструментала.

## Confirmed / risks

  символ вставляется в позицию каретки либо заменяет выделенный фрагмент, после
  чего фокус и каретка возвращаются в поле. Добавлена Playwright-регрессия для
  обоих вариантов; `validate:a1`/TypeScript и целевой UI-тест успешны.
- Текущий шаг: `validate:a1`/TypeScript, production build и Playwright
  `47 passed` успешны. UI-сценарии тем 11–14 проверяют количество учебных
  шагов, отдельные финальные тесты, построчные ошибки, допустимые ответы и
  исправление форм. Direct tests подтверждают deterministic mistake
  schedule, immutable summary и scoped reset с preservation внешних данных;
  прежние UI paths review/reset/final/restore/reinforcement остаются зелёными.
- Предыдущая полная матрица: backend `11 passed`, compileall, launcher и
  repository audit — успешно. Финальный этап переименования повторно
  подтвердил backend `11 passed` с одним известным Starlette warning,
  compileall, launcher self-test и repository audit; запрещённых путей и
  credential-like значений в 206 кандидатных файлах не найдено.
- Backup рабочего дерева и Git history находится в ignored
  `_git-package/checkpoints/`.
- UI-аудит подтвердил корректные answer gating, feedback по диакритике,
  сохранение шага/ответа после reload, ошибочный и успешный итоговый тест
  (`50%` → `100%`) и переход к Module 2. Основные темы, dark mode и AI settings
  modal не создают page-level overflow на ширине 390 px.
- Исправлено: `/vocabulary/sync` использует существующий UNIQUE
  `(lesson_slug, word)` как conflict target атомарного UPSERT. Regression test
  проверяет повторный и два одновременных запроса, а также сохранение
  `review_count`/`interval_days` после последующей синхронизации. Backend:
  `11 passed`, compileall успешно.
- Исправлено: breakpoint шапки поднят до 1050 px. Автотест и browser QA при
  768 px подтверждают, что document/header/settings остаются внутри viewport.

  чтобы переключатель шириной 100% не создавал overflow. Добавлена
  Playwright-регрессия по фактической геометрии элементов.

  Автотест и browser QA при 390 px + extra-large font подтверждают скрытый
  список, отсутствие overflow и расстояние 14 px между selector и article.

## Continue here

Module 1 принят и завершён. Следующую содержательную работу начинать с Module 2,
сохраняя его lesson slugs, activity IDs и текущие совместимые контракты.

Content path стабилизирован. Обновление существующей темы меняет только её
`lessons/<slug>.ts`. Новая тема Modules 2–6 требует roadmap entry, отдельный
lesson-файл и одну регистрацию lesson-объекта в группе своего `moduleN/index.ts`;
ручное редактирование `lessonSlugs`, `a1Course.ts` и счётчиков запрещено. Для
Modules 7–8 маршрут тот же, но регистрируется compact content-объект. После
любого изменения запускать `npm.cmd run validate:a1` и релевантный UI-тест.

Не продолжать механическое дробление frontend. Tutor UI намеренно отложен;
dormant backend tutor contract не менять без нового явного запроса владельца.

Не менять API, SQLite, browser-storage keys, slug или activity ID.
