## Архитектурное расширение — начато 2026-08-30

Целевая форма проекта — модульный монолит с явными frontend/backend
границами. Текущий single-user и loopback-only scope сохраняется; каждый этап
должен оставлять рабочий Slovak A1 и проходить существующую test matrix.

### Этап 1 — безопасная декомпозиция текущего runtime

- [x] Создать проверенный локальный backup рабочего дерева и Git-истории до
  архитектурных изменений.
- [x] Вынести чистую логику проверки ответов, повторения и итоговых тестов из
  `CourseScreen.tsx`, сохранив поведение и стабильные activity ID.
- [x] Свести учебное состояние к typed actions и выделить persistence/hydration
  из UI-компонента.
- [x] Разделить экран курса на самостоятельные feature-view и hooks без
  добавления нового глобального state framework.
- [x] Разделить backend course-router на тонкие доменные границы для state,
  exercises, reading, vocabulary и homework, не меняя публичные URL.
- [ ] Добавить URL-навигацию до module/lesson при сохранении `/` как
  канонического входа.

Критерий завершения: UI/API-поведение, SQLite и совместимые browser-storage
ключи не изменены; content validation, TypeScript, backend, Playwright, build и
repository audit проходят.

### Этап 2 — идентичность и версия курса

- [ ] Ввести `CourseDefinition` с `courseId`, `levelId` и `contentVersion`,
  сохранив текущий Slovak A1 единственным runtime-курсом.
- [ ] Спроектировать `CourseStateV2` и явный compatibility-переход из v1.
- [ ] Перед физическим изменением SQLite ввести Alembic, резервную копию и
  тесты на старой/новой базе; затем добавить course/level identity в
  persistent-сущности.
- [ ] Заменить внутреннее имя `module1-chat` универсальным tutor-контрактом,
  временно сохранив compatibility alias.
- [ ] Автоматизировать проверку соответствия FastAPI OpenAPI и frontend
  TypeScript-клиента.

Критерий завершения: новый уровень или курс можно добавить без hard-coded
лимита модулей и без смешивания его прогресса с текущим Slovak A1.

### Этап 3 — учебные события и адаптация

- [ ] Добавить отдельные записи попыток, ошибок, повторений, tutor-сессий и
  module assessment; JSON-снимок оставить только для быстрого восстановления
  UI.
- [ ] Рассчитывать mastery и рекомендации следующего шага из подтверждённых
  попыток, а не только из текущего snapshot.
- [ ] Улучшить интервальное повторение с оценкой качества ответа и историей
  review events.
- [ ] Добавить локальный экспорт/импорт прогресса с проверкой версии схемы.

### Этап 4 — новые возможности курса

- [ ] Добавить расширяемую discriminated-union модель активностей перед
  listening, speaking, dialogue и составными заданиями.
- [ ] Реализовать аудирование и произношение только после решения политики
  хранения локального аудио.
- [ ] Добавить инструменты подготовки и проверки контента для следующих
  уровней без введения runtime CMS.

Multi-user/auth, PostgreSQL, микросервисы, облачный deployment и синхронизация
между устройствами остаются отдельными проектами и не входят в эти этапы.
