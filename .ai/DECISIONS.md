# Architecture Decisions

## ADR-001: Один локальный пользователь в раннем MVP

Статус: принято.

Решение:
Не реализовывать регистрацию и авторизацию до появления рабочего учебного цикла.

Причина:
Авторизация не проверяет основную ценность продукта и замедляет разработку.

Последствия:
- данные раннего MVP принадлежат одному локальному пользователю;
- модели должны позволять позже добавить `user_id` или полноценную модель User;
- перед публичным запуском потребуется миграция к многопользовательской модели.

## ADR-002: Модульный монолит

Статус: принято.

Решение:
Использовать один FastAPI backend, разделенный на модули и сервисы.

Причина:
Для MVP микросервисы добавят сложность без практической пользы.

## ADR-003: SQLite сначала, PostgreSQL позже

Статус: принято.

Решение:
Использовать SQLite для локальной разработки и первого прототипа.

Причина:
Минимальная настройка и быстрый запуск.

Условие перехода:
Появление регистрации, нескольких пользователей или production deployment.

## ADR-004: Структурированные ответы AI

Статус: принято.

Решение:
Ответы AI, влияющие на состояние приложения, должны возвращаться в JSON и валидироваться.

Причина:
Свободный текст нельзя надежно использовать для обновления прогресса и классификации ошибок.

## ADR-005: Контент курса отделен от кода

Статус: принято.

Решение:
Курсы описываются в YAML или JSON и загружаются через course engine.

Причина:
Это позволит добавлять Python, математику и другие предметы без переписывания ядра.

## ADR-006: Next.js как основной frontend с совместимым учебным UI

Статус: принято.

Решение:
Основной интерфейс запускается через Next.js на порту 3000. Уже проверенная
учебная логика статического интерфейса временно остаётся в `public/legacy` и
отображается через same-origin iframe; Next.js проксирует API к FastAPI.

Причина:
Это переносит MVP на заданный стек без регрессии существующих упражнений,
чата, аналитики ошибок и локального API.

Последствия:
- Next.js отвечает за точку входа, проксирование API и настройку темы;
- тёмная тема хранится локально в браузере и применяется к учебному UI;
- постепенное разбиение legacy-интерфейса на React-компоненты остаётся
  отдельной задачей и не блокирует работу MVP.
