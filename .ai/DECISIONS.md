# Architecture Decisions

## ADR-001: Один локальный пользователь в раннем MVP

Статус: принято.

Решение:
Не реализовывать регистрацию и авторизацию до появления рабочего учебного цикла.

Причина:
Авторизация не проверяет основную ценность продукта и замедляет разработку.

Последствия:
- данные раннего MVP принадлежат одному локальному пользователю;
- модели должны позволять позже добавить `user_id` или полноценную модель User;
- перед публичным запуском потребуется миграция к многопользовательской модели.

## ADR-002: Модульный монолит

Статус: принято.

Решение:
Использовать один FastAPI backend, разделенный на модули и сервисы.

Причина:
Для MVP микросервисы добавят сложность без практической пользы.

## ADR-003: SQLite сначала, PostgreSQL позже

Статус: принято.

Решение:
Использовать SQLite для локальной разработки и первого прототипа.

Причина:
Минимальная настройка и быстрый запуск.

Условие перехода:
Появление регистрации, нескольких пользователей или production deployment.

## ADR-004: Структурированные ответы AI

Статус: принято.

Решение:
Ответы AI, влияющие на состояние приложения, должны возвращаться в JSON и валидироваться.

Причина:
Свободный текст нельзя надежно использовать для обновления прогресса и классификации ошибок.

## ADR-005: Контент курса отделен от кода

Статус: принято.

Решение:
Курсы описываются в YAML или JSON и загружаются через course engine.

Причина:
Это позволит добавлять Python, математику и другие предметы без переписывания ядра.

## ADR-006: Next.js как основной frontend с совместимым учебным UI

Статус: принято.

Решение:
Основной интерфейс запускается через Next.js на порту 3000. Уже проверенная
учебная логика статического интерфейса временно остаётся в `public/legacy` и
отображается через same-origin iframe; Next.js проксирует API к FastAPI.

Причина:
Это переносит MVP на заданный стек без регрессии существующих упражнений,
чата, аналитики ошибок и локального API.

Последствия:
- Next.js отвечает за точку входа, проксирование API и настройку темы;
- тёмная тема хранится локально в браузере и применяется к учебному UI;
- постепенное разбиение legacy-интерфейса на React-компоненты остаётся
  отдельной задачей и не блокирует работу MVP.

## ADR-007: Поэтапное выделение backend-роутеров

Статус: принято.

Решение:
Сохранять один FastAPI backend, но постепенно переносить независимые HTTP
маршруты, их Pydantic-схемы и зависимости в доменные модули. Первым выделен
`app.routers.tutor` для Codex-статуса, входа и единичного сообщения
преподавателю.

Причина:
`main.py` содержит слишком много разнородных маршрутов. Пошаговое выделение с
полным регрессионным набором уменьшает риск изменения внешнего API.

Последствия:
- URL, JSON-контракты и `app.dependency_overrides` сохраняются;
- общие AI-helper-функции остаются в `main.py`, пока их используют несколько
  доменов;
- после `tutor` выделен `courses` для каталога и study-roadmap, затем основные
  маршруты `practice`; далее progress и словарные функции.
- state-changing сценарий ответа урока живёт в `services/lesson_answers`;
- общие helpers ошибок и словаря выделены в `services/learning_state`, потому
  что их вызывают упражнения, диалоги, дневник, домашние задания и тесты.
- practice-router владеет всеми маршрутами урока; локальная числовая проверка
  вынесена в `services/answer_checking`, чтобы не импортировать `main.py`.
- read-only сводка прогресса и мутации ошибок выделены в `routers/progress`.
- read-only список ошибок выделен в `routers/progress`, а shared lookup названия
  урока — в `services/lesson_lookup`.
- все общие vocabulary-маршруты, их Pydantic-контракты и преобразование модели
  ответа выделены соответственно в `routers/vocabulary`, `schemas/vocabulary`
  и `services/vocabulary`; endpoint словаря отдельного урока пока остаётся в
  `main.py` как часть lesson-сценария.

## ADR-008: Ограниченный локальный запуск Python-кода

Статус: принято.

Решение:
Добавить отдельный Python-курс в YAML и endpoint запуска учебного кода. Код
выполняется в отдельном процессе с лимитом 3 секунды и ограниченным набором
встроенных функций. Импорты, сеть, файловая система, GUI и приватные атрибуты
не доступны в браузерном редакторе.

Причина:
Ученик должен сразу видеть результат коротких программ, но локальный MVP не
является безопасной средой для произвольного кода или размещения веб-сервисов.

Последствия:
- базовые задачи, условия, циклы, структуры данных, функции и классы можно
  запускать прямо в курсе;
- `math` и `random` доступны как подготовленные объекты без `import`;
- проекты с файлами, HTTP, Flask, Pandas, Telegram, Tkinter и пакетами
  запускаются только в локальном Python-окружении пользователя;
- для публикации или многопользовательского запуска потребуется настоящая
  изолированная песочница уровня контейнера/VM.

## ADR-009: Массовое подтверждение ошибок ограничено курсом

Статус: принято.

Решение:
Действие «Исправить всё» в разделе ошибок подтверждается пользователем и
отмечает исправленными только активные записи выбранного `course_slug`.

Причина:
Словацкий язык и математика имеют отдельную аналитику ошибок; массовое действие
не должно закрывать ошибки другого предмета или выполняться случайно.

Последствия:
- backend возвращает число закрытых записей;
- UI обновляет текущий список после успешного запроса;
- индивидуальное подтверждение ошибки сохраняется.
