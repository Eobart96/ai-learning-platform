# Development Conventions

## Общие правила

- Делать небольшие изменения, соответствующие одной задаче.
- Не менять архитектуру без записи в `DECISIONS.md`.
- Не добавлять зависимости без причины.
- Не оставлять неиспользуемый код.
- Не скрывать ошибки пустыми `except`.
- Не коммитить `.env`, ключи и токены.

## Python

- Python 3.12+.
- Type hints обязательны для публичных функций.
- Pydantic используется для API-схем и валидации AI-ответов.
- SQLAlchemy 2.x style.
- Имена файлов и функций: `snake_case`.
- Имена классов: `PascalCase`.
- Форматирование: Ruff.
- Тесты: pytest.

## FastAPI

- Базовый API-префикс: `/api/v1`.
- Служебный `/health` может находиться без префикса.
- Роутеры не должны содержать сложную бизнес-логику.
- Бизнес-логика размещается в сервисах.
- Ошибки API должны быть понятными и стабильными.

## TypeScript и React

- TypeScript strict mode.
- Функциональные компоненты.
- Компоненты не должны напрямую знать детали базы данных.
- API-вызовы выносятся в отдельный слой.

## Git

Формат коммитов:

- `feat: ...`
- `fix: ...`
- `docs: ...`
- `test: ...`
- `refactor: ...`
- `chore: ...`

## Definition of Done

Задача считается выполненной, когда:

- код запускается;
- тесты проходят;
- документация обновлена;
- нет секретов;
- нет очевидных заглушек, выдаваемых за готовую функцию.
